When should I use AP mode?

Use it for a quick one-to-one demonstration, first-time setup or a lab where you want to connect directly to the board without configuring the office network.

Virtual mode: Walk through a simulated router, board and laptop connection. The example IP address is for learning only.

When should I use STA mode?

Use it when the board needs to be part of an existing lab or office network, where it can communicate with PCs, dashboards, brokers and other devices.

Virtual mode: Watch example publish and subscribe messages move between a simulated board, broker and Node-RED dashboard.
Hardware mode: Connect the actual board to a reachable MQTT broker and verify the topic names and payloads used by its firmware.

Simple explanation

Think of the broker as a post office

The board sends a message such as “DI1 is ON” to the broker. Node-RED subscribes to that topic and receives it. When you press a Node-RED button, it publishes a command such as “DO1 ON”; the board receives that command and changes the output.

Publish means send a message. Subscribe means listen for messages on a topic.

Your PowerPoint setup

Local Aedes broker

  1. Run Node-RED on your PC and add the Aedes broker node.
  2. Set the broker port to 1883 and deploy the flow.
  3. Configure the board with your PC's IPv4 address — not localhost.
  4. Use localhost inside Node-RED when it connects to the broker running on that same PC.
Both the board and the PC must be on the same network for this local-broker example.
My recommendation for this public website

Start with USB serial for the first Local I/O exercise. Add MQTT as an advanced network lesson. If the public website will control a board over the internet, use a broker with secure WebSocket (WSS), user authentication and per-device topics. Do not put private broker credentials in public JavaScript.
